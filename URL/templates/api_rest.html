Introducción

La API REST de PhishShield te permite integrar nuestro sistema de análisis de URLs en tus aplicaciones. Todos los endpoints devuelven respuestas en formato JSON y utilizan métodos HTTP estándar.

🚀 Características de la API

  • Respuestas JSON estructuradas y consistentes
  • Múltiples motores de análisis (PhishTank, VirusTotal, IA heurística)
  • Base de datos normalizada con cache inteligente
  • Estadísticas completas y historial de análisis
  • Sin autenticación requerida para uso básico

Autenticación

Actualmente la API es de acceso público y no requiere autenticación. Para uso empresarial o altos volúmenes de requests, contáctanos para obtener una API key.

⚠️ Límites de Uso

  • Máximo 100 requests por hora por IP
  • Cache de 24 horas para URLs repetidas
  • Timeout de 30 segundos por análisis
  • Uso comercial requiere licencia

Ejemplos de Uso

🐍 Python

import requests

response = requests.post(
  "http://localhost:5000/analyze",
  json={"url": "https://ejemplo.com"}
)
data = response.json()
print(f"Riesgo: {data['risk_score']}/10")
print(f"Malicioso: {data['is_malicious']}")

🟨 JavaScript

fetch('http://localhost:5000/analyze', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ url: 'https://ejemplo.com' })
})
.then(response => response.json())
.then(data => {
  console.log(`Riesgo: ${data.risk_score}/10`);
  console.log(`Malicioso: ${data.is_malicious}`);
});

🔗 cURL

curl -X POST http://localhost:5000/analyze \
  -H "Content-Type: application/json" \
  -d '{"url": "https://ejemplo.com"}'

Códigos de Error

4xx - Errores del Cliente

  • 400 - Bad Request (URL inválida o faltante)
  • 404 - Not Found (Endpoint no existe)
  • 429 - Too Many Requests (Límite excedido)

5xx - Errores del Servidor

  • 500 - Internal Server Error
  • 502 - Bad Gateway (APIs externas no disponibles)
  • 504 - Gateway Timeout

💡 Notas Importantes

  • El endpoint /analyze puede tardar 5-15 segundos dependiendo de las APIs externas
  • Los resultados se cachean por 24 horas para URLs repetidas
  • Todas las respuestas incluyen timestamps y metadatos de análisis
  • Para uso en producción, considera implementar retries y timeouts
